개요 Pensieve가 무엇이고 어떻게 동작하나

Pensieve는 Claude Code에 영속 기억을 붙이는 로컬 시스템입니다. Claude Code의 훅(hook) 메커니즘에 올라타, 대화에서 의미 있는 사실을 자동으로 Markdown 파일에 저장하고, 다음 대화에서 다시 컨텍스트로 주입합니다. 별도 서버·계정·네트워크 없이 각 PC의 ~/.claude/ 안에서만 동작합니다.

핵심 아이디어 4가지

① 자동 저장 (Capture)

사용자 메시지를 정규식으로 분류(선호/교정/실패/컨벤션)하고, 대화 종료 시 LLM이 한 번 더 훑어 "오래 쓸 사실"만 골라 파일에 추가합니다. 사용자가 시키지 않아도 동작합니다.

② 자동 주입 (Recall)

세션 시작 시 무거운 스냅샷(정체성+프로젝트 기억+글로벌 요약)을 1회, 매 턴은 경량 컨텍스트 + 질문 연관 자동회상을 주입합니다. 10K 출력 한도 안에 들어가도록 계층별로 잘립니다.

③ 2중 저장소

사람이 읽고 고칠 수 있는 Markdown이 1차 원본(source of truth)이고, SQLite FTS5가 전문검색용 거울입니다. SQLite가 없어도 Markdown만으로 동작합니다.

④ 자가 정비

용량 초과 시 오래된 항목을 밀어내고(FIFO), 유사 항목은 Jaccard로 병합하며, 추출 프롬프트·시스템 태그 같은 노이즈는 자동 청소합니다. 밀려난 항목도 SQLite에 남아 검색됩니다.

한 문장 요약: 사용자 메시지·대화 → (분류·LLM 추출) → Markdown 파일 + SQLite → 다음 세션·턴마다 컨텍스트로 다시 주입. 이 순환이 "이 친구가 나를 기억한다"는 체감을 만듭니다.

훅 생명주기 memory-hook.js가 4개 이벤트에 어떻게 반응하나

Claude Code가 특정 시점에 memory-hook.js에 stdin으로 JSON을 넘기면, 훅은 이벤트명으로 분기합니다. 읽기(주입)는 SessionStart·UserPromptSubmit에서, 쓰기(저장)는 UserPromptSubmit·Stop 계열에서 일어납니다.

SessionStart → handleSessionStart()
세션당 1회. 무거운 "동결 스냅샷"을 주입 — 정체성(<who>) + 행동카드 + 프로젝트 메모리 전문 + 글로벌 다이제스트. --resume 시 재실행되어 세션 내내 유지되므로 매 턴은 가볍게 갈 수 있음.
↓
UserPromptSubmit → handleUserPrompt()
쓰기: classifyAndSave(prompt)로 즉시 정규식 분류 저장.
읽기: 경량 컨텍스트(perTurnLight) + 이번 질문에 연관된 <recalled-memory> 자동회상 주입.
카운터(promptCount, turnsSinceReview) 증가 → 임계 도달 시 백그라운드 리뷰 spawn.
↓
PostToolUse → handlePostToolUse()
툴 호출마다 카운터(toolCallsSinceReview, totalToolCalls) 증가. nudgeToolCalls(기본 15) 도달 시 백그라운드 리뷰를 detached로 spawn. 주입은 하지 않음.
↓
Stop / SubagentStop / PreCompact → handleStopLike()
대화 종료 시 본격 정리: ① LLM 추출기로 transcript 끝부분에서 durable 후보 추출 → 저장 ② 사용자 메시지 정규식 재분류 ③ 세션 인덱싱(PreCompact 제외) ④ 노이즈 자동청소 ⑤ Jaccard 자동병합. state에 결과 기록.

백그라운드 리뷰 트리거 조건

조건기본값설명
turnsSinceReview ≥ nudgeInterval10 턴턴 수 누적
toolCallsSinceReview ≥ nudgeToolCalls15 호출툴 호출 누적
backgroundReviewEnabled && useLlmExtractor둘 다 true꺼져 있으면 spawn 안 함
CLAUDE_HERMES_CHILD !== '1'—자식 프로세스 재귀 방지
참고: 둘 중 하나라도 임계에 도달하면 메인 세션을 막지 않는 detached 프로세스로 background-review.js를 띄우고, 카운터를 0으로 리셋합니다. PowerShell 파이프로는 stdin이 훅에 제대로 전달되지 않아 검증 시 Bash로 stdin을 넘겨야 합니다(알려진 이슈).

주입 (읽기) composeContext()가 쌓는 컨텍스트 계층

주입은 2계층 설계입니다. SessionStart = 무거운 스냅샷(1회), UserPromptSubmit = 경량 + 자동회상(매 턴). 아래 계층 중 초록은 항상, 노랑은 무거운 스냅샷에서만 주입됩니다.

항상 (every turn, light 포함) 무거운 스냅샷에서만 (!light)
<memory-policy>저장/회상 행동 정책. 스타일: full·compact·custom·none (legacy-inject 모드면 생략)
<memory-active-project>현재 활성 프로젝트 slug
<memory-save-notice>직전 턴에 저장된 게 있으면 "💾 저장:" 한 줄로 사용자에게 알림
<who>정체성 카드 — USER.md 상단 큐레이션(프로필·선호·작업스타일). "사용자가 누구인가"를 항상 고정 (≤1200자)
<behavior-rules>행동 카드 — BEHAVIOR.md(글로벌+프로젝트). 최우선 규칙, tail/한도 잘림 우회 (≤2000자)
<recall-behavior>"기억하는 사람처럼 답하라, '기억 안 난다' 먼저 말하지 마라" 지침
<recalled-memory>자동 회상 — 이번 프롬프트를 FTS 검색해 연관 기억을 그대로 주입 (≤6건, ≤1500자). 스냅샷에 안 떠도 "그건 저장돼 있다"를 보장
<global-digest>글로벌 MEMORY/FAILURES/SKILLS/PROJECTS의 최근 항목을 압축·중복제거 (project 모드 전용, ≤1500자)
<memory-context>원문 덤프 — 모드에 따라 프로젝트(+글로벌) 메모리 전문. 파일당 tail 2500자, 전체 injectCharLimit 8000자

주입 모드 (memoryMode)

모드덤프 범위다이제스트특징
project 기본프로젝트 메모리 전문O (글로벌 압축)프로젝트 기억 우선. 글로벌은 요약+검색

저장 (쓰기) appendEntry()의 파이프라인

모든 저장은 files.js의 appendEntry()를 통과합니다. 입력은 먼저 분류기를 거치고, 안전 필터·중복·용량 정책을 통과한 뒤 Markdown에 추가되고 SQLite에 미러됩니다.

1단계 · 분류 (classify.js)

사용자 메시지를 정규식으로 분류. sanitizeInput()이 시스템 태그(<memory-*>, <system-reminder> 등)를 먼저 제거하고, 800자 초과 입력은 무시합니다.

패턴예시 트리거저장 대상
preference앞으로 / 항상 / 선호 / prefer / alwaysUSER.md (글로벌)
explicitMemory기억해 / 메모해 / remember thisMEMORY.md
correction아니야 / 틀렸 / no actuallyFAILURES.md (Correction:)
failure실패 / 에러 / failed / brokenFAILURES.md (Failure:)
convention우리는 / 이 레포는 / we useCONVENTIONS.md (프로젝트 활성 시만)

용량 초과 전략 (memoryOverflowStrategy)

전략동작

핵심 보장: 파일 용량 한도(20K)는 "주입에 들어갈 분량"을 제한하기 위한 것이고, 밀려난 기억은 SQLite 확장 저장소에 살아있어 /memory-search로 언제든 되살릴 수 있습니다. 즉 잊는 게 아니라 책상에서 서랍으로 옮기는 구조입니다.

SQLite & 검색 db.js — 전문검색 거울

~/.claude/memory/sessions.db는 better-sqlite3로 열리는 FTS5 인덱스입니다. 드라이버가 없으면 조용히 Markdown 전용으로 폴백합니다(loadDriver() → null). WAL 모드로 동작합니다.

스키마 (4 테이블 + 2 FTS 가상테이블)

📝 memories

모든 저장 엔트리의 거울. 컬럼: created, scope, project, target, source, category, content, is_extended. is_extended=1은 파일에서 밀려났지만 검색용으로 남은 항목.

🔍 memories_fts

FTS5 외부콘텐츠 인덱스. INSERT/DELETE 트리거로 memories와 자동 동기화. snippet()으로 매치 부분 하이라이트.

💬 sessions / session_messages

대화 transcript 인덱싱. 세션 메타(first_ts, last_ts, message_count)와 개별 메시지(role·ts·content, UNIQUE 제약으로 중복 방지).

🔎 session_fts

세션 메시지 전문검색. /memory-search --sessions로 과거 대화 내용을 찾을 때 사용.

주요 쿼리 함수

함수용도
mirrorMemory()저장 시 memories에 INSERT (FTS 트리거 자동 반영)
searchMemories(q)/memory-search의 본체. MATCH + rank 정렬 + snippet
recallMemories(q)자동 회상용. 프롬프트를 토큰화 → OR 쿼리로 만들어 임의 텍스트가 FTS5 문법 오류를 안 내게 함. 전문(content) 반환

자동 회상이 안전한 이유: recallMemories()는 동기 훅 안에서 호출되지만 FTS 검색은 sub-ms라 블로킹이 없습니다. 사용자가 무슨 문자를 입력하든 토큰만 뽑아 "tok1" OR "tok2" 형태로 감싸므로 특수문자로 인한 예외가 발생하지 않습니다.

백그라운드 & 유지관리 메인 세션을 막지 않는 정비 작업

백그라운드 리뷰 (background-review.js)

PostToolUse/UserPromptSubmit에서 임계 도달 시 detached 프로세스로 분리 실행됩니다. 메인 대화를 멈추지 않고 claude -p로 transcript를 한 번 더 정밀 추출합니다.

🧠 메모리 추출

transcript 끝 30메시지(≤12000자)에서 durable 후보를 JSON으로 추출 → appendEntry()

⚙️ 스킬 자동 추출

skillAutoExtract 켜짐 시, 재사용 가능한 완결 절차를 발견하면 최대 2개까지 createSkill() (충돌 가드 통과 필요)

🧹 노이즈 청소

추출 직후 cleanAll() 1회 실행. 결과는 state/<session>.bg.json에 기록

노이즈 청소 (noise-detector.js)

분류기가 잘못 삼킨 "메모리 같지 않은" 항목을 패턴으로 찾아 제거합니다. Stop 계열과 백그라운드 리뷰 후 자동 실행되며(autoCleanNoise 기본 true), 삭제는 state/cleanup-log.jsonl에 남깁니다.

노이즈 종류예시
llm-extraction-prompt"Extract durable memory candidates…", "Return ONLY JSON array" 같은 추출 프롬프트 자가 누출
slash-command-definition# memory-, # wcc: 등 슬래시 명령 정의 본문
system-tag-block<system-reminder>, <memory-policy>, <command-name>이 사용자 메시지로 캡처됨
wrapped-slash-commandFailure:/Correction:으로 감싸진 슬래시 명령 정의 (분류기 오탐)

자동 병합 & 정비

🔗 auto-consolidate (Jaccard)

Stop 시 consolidateFileSimilar()가 토큰 Jaccard 유사도 ≥ 임계(autoConsolidateThreshold)인 근접 중복을 병합. 한국어/영어 토큰 지원. 제거분은 SQLite 미러에서도 삭제.

🗑️ prune & consolidate 명령

/memory-prune N일 경과 항목 GC, /memory-consolidate 중복 제거(--llm은 claude -p 의미 병합), /memory-clean-noise 수동 청소.

안전 계층 3종

🔐 secrets.js

API 키·토큰·비번 형태 차단. 저장 전 필수 통과

🛡️ content-scanner.js

프롬프트 인젝션(영/한) 차단. blockPromptInjection 토글

🧼 noise-detector.js

비메모리 노이즈 사후 청소. 로그 남김

왜 인젝션 스캔이 중요한가: 메모리는 다음 세션에 컨텍스트로 다시 주입됩니다. 악의적 "이전 지침을 무시하라" 텍스트가 저장되면 미래의 Claude가 그걸 읽게 되므로, 저장 시점에 차단해 메모리를 통한 지연 공격을 막습니다.

설정 & 명령어 hermes-memory-config.json + 슬래시 명령

설정은 ~/.claude/hermes-memory-config.json에서 읽고, 없는 키는 config.js의 DEFAULTS가 자동 채웁니다. 따라서 업데이트 시 config 수동 수정 없이도 신규 키가 적용됩니다.
